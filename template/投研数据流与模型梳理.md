# `template/` 投研数据流与模型梳理

本文按“数据流 + 模型家族 + 实际投研动作”来梳理 `template/` 目录。

说明：
- 只覆盖源码与说明文档，不包含 `__pycache__`、`tmp` 这类运行产物目录。
- 只覆盖当前 `template/` 主流程，不展开 `archive/template_legacy/` 历史代码。
- 文中会特别区分“当前主流程直接使用”和“支撑/兼容/备用”文件，避免阅读时混淆。

## 1. 从数据流角度看整套主流程

### 1.1 总体流程

当前主流程可以概括为：

`配置 -> 扫描 parquet 元信息/选特征 -> 时间切分 -> 预处理拟合 -> 训练/验证 -> 评估 -> 落盘 run 目录产物`

更细一点：

1. 在 `template/runners/train.py` 里解析命令行参数。
2. 根据 `--family` 选择基线配置：
   - `lgbm` -> `template/configs/presets/baseline_lgbm.py`
   - `xgb` -> `template/configs/presets/baseline_xgb.py`
   - `nn` -> `template/configs/presets/baseline_nn.py`
3. 用 `template/configs/pipeline_config.py` 中的统一配置骨架承接这些参数。
4. 把 `PipelineConfig.data` 转为 `LargeParquetConfig`，交给 `template/data/parquet_adapter.py` 和 `template/data/io_parquet.py` 读取 parquet。
5. 在 `template/data/parquet_adapter.py` 里发现 `f0~fN` 因子列，并按 `feature_mode` 选择特征。
6. 用 `template/data/io_parquet.py` / `template/data/split.py` 得到 `train_end / val_end` 这些时间边界。
7. 用 `template/data/preprocess.py` 在训练段拟合填充/裁剪/标准化状态，再把同一套状态作用到验证、holdout 或外部测试数据。
8. 分成两条训练支路：
   - GBDT：进入 `template/train/gbdt_trainer.py`
   - NN：先做轻量扫描与流式预处理，再进入 `template/data/nn_samples.py` 以滑窗缓冲区方式构样本，最后进入 `template/train/torch_trainer.py`
9. 训练完成后输出模型文件、预测文件、`meta.json` 和指标，统一落到 `res/pipeline/<family>/<run_id>/` 风格目录。
10. 如需独立预测或独立评估，再用：
   - `template/runners/predict.py`
   - `template/runners/evaluate.py`

### 1.2 两条主分支

#### GBDT 分支

数据流是：

`train.py -> parquet_adapter/io_parquet -> split -> preprocess -> GBDTTrainer -> lgbm/xgb wrapper -> run_dir(model.pkl + meta.json + test_pred.parquet)`

特点：
- 面向表格特征直接训练，不需要把 panel 变成序列样本。
- 训练阶段仍以表格批量训练为主，但预测阶段支持对外部 `test.parquet` 做流式推理。
- 训练、独立预测、独立评估三条链路都已统一输出 `prediction` 与复合键列。

#### NN 分支

数据流是：

`train.py -> scan_train_metadata -> fit_preprocessor_streaming -> build_nn_samples_streaming -> registry/build_nn_model -> TorchTrainer -> run_dir(model.pt + meta.json + test_pred.parquet)`

特点：
- 先扫描训练数据得到时间边界和特征列，再流式拟合预处理状态。
- 构样本时不再要求整表面板常驻内存，而是按 `stockid` 维护有限长度滑窗缓冲区。
- 模型选择通过 `template/models/registry.py` 完成。
- 训练完成后同样可以通过统一的 `template/runners/predict.py` 对外部 `test.parquet` 做推理。

### 1.3 你在投研里最常接触的输出

- 模型文件：
  - GBDT：`model.pkl`
  - NN：`model.pt`
- 预测文件：`test_pred.parquet`
  - 列结构固定为：
    - `stockid|dateid|timeid`
    - `prediction`
- 元信息：`meta.json`
- 评估输出：控制台 JSON 或额外保存的评估 JSON
- 典型目录：`res/pipeline/<family>/<run_id>/`

最关键的是 `meta.json`，因为它同时记录：
- `metrics`
- `feature_cols`
- `preprocess_state`
- `data_config`
- `model_config` 或 `nn_config`
- `train_end / val_end`
- `id_map` 与 `num_ids`（NN）

## 2. 按模型家族分类看 `template/` 内每个文件的作用

## 2.1 共享基础设施：不属于某个单一模型，但所有模型都会经过

### 根目录

- `template/README.md`
  - 当前重构版模板的总说明，告诉你主入口、目录职责和常用命令。

### `template/runners/`：统一命令行入口层

- `template/runners/__init__.py`
  - runner 包标记文件，说明这里放的是训练/预测/评估入口。
- `template/runners/train.py`
  - 最核心入口，统一训练 `lgbm/xgb/nn`。

  - 已持久化 `lgbm/xgb/nn` 模型的统一独立预测入口。

- `template/runners/smoke.py`
  - 用小样本做冒烟测试，检查各条链路能否跑通。

### `template/configs/`：统一配置层

- `template/configs/__init__.py`
  - 对外统一导出配置 dataclass。
- `template/configs/pipeline_config.py`
  - 当前主流程最重要的总配置骨架。
  - 里面定义了：
    - `DataConfig`
    - `PreprocessConfig`
    - `ModelConfig`
    - `RunnerConfig`
    - `NNConfig`
    - `PipelineConfig`

  - NN 相关参数集中在 `NNConfig`（即 `PipelineConfig.nn`）；训练时直接使用 `cfg.nn`，预测时从 `meta["nn_config"]` 通过 `nn_config_from_meta(d)` 恢复为 `NNConfig`。
- `template/configs/presets/__init__.py`
  - 导出三个 baseline preset。
- `template/configs/presets/baseline_lgbm.py`
  - LGBM 的默认超参与默认输出目录。
- `template/configs/presets/baseline_xgb.py`
  - XGB 的默认超参与默认输出目录。
- `template/configs/presets/baseline_nn.py`
  - NN 的默认预处理方式、网络超参和输出目录。

### `template/data/`：统一数据入口与预处理层

- `template/data/__init__.py`
  - 汇总导出数据读取、切分、预处理、样本构造工具。
- `template/data/parquet_adapter.py`
  - 大 parquet 适配核心文件。
  - 负责：
    - 发现因子列
    - 按 `feature_mode` 选择特征
    - row-group/batch 方式流式读取
    - 控制最大读取行数
    - 训练/验证/测试日期边界计算
- `template/data/io_parquet.py`
  - 把 parquet 读写动作再封装一层。
  - 负责：
    - `scan_train_metadata`
    - `load_train_panel`
    - `iter_test_batches`
    - `stream_predictions_to_parquet`
- `template/data/preprocess.py`
  - 统一特征预处理。
  - 负责：
    - 缺失值填充
    - 分位数裁剪
    - 多种标准化模式
    - 保存和复用 `PreprocessorState`
  - 当前支持：
    - `global`
    - `cross_section`
    - `date`
    - `time_rolling`
- `template/data/split.py`
  - 根据 `train_end`、`val_end` 做按时间切分。
- `template/data/nn_samples.py`
  - 仅供 NN 分支使用。
  - 既保留面向整表的滑窗样本工具，也新增了更贴近主流程的流式构样本能力。
  - 把数据按 `id + lookback` 变成滑窗样本：
    - `train`
    - `val`
    - `test`

### `template/train/`：统一训练执行层

- `template/train/__init__.py`
  - 统一导出训练相关对象与函数。
- `template/train/gbdt_trainer.py`
  - GBDT 训练器。
  - 负责：
    - 构造训练/验证矩阵
    - ranking 目标下的分组与 relevance 转换
    - holdout 上计算 `mse/mae/r2/ic/rankic`
    - 保存模型
- `template/train/torch_trainer.py`
  - NN 训练主文件，也是 `NN` 分支的核心执行器。
  - 负责：
    - device/AMP
    - Dataset/DataLoader
    - 普通 batch 与按日 batch
    - 训练/验证/预测循环
    - 最终封装为 `TorchTrainer`
- `template/train/losses.py`
  - PyTorch 损失函数集合。
  - 不只支持 `mse/huber/quantile`，还支持 IC/RankIC 风格损失。
- `template/train/checkpoint.py`
  - 最佳模型追踪、早停和 checkpoint 管理。
  - 当前支持按 `val_loss / val_ic / val_rankic / val_r2` 选最佳模型。

### `template/eval/`：统一评估、回测、记录层

- 快速比较 `LabelA/LabelB/LabelC`
- 快速验证 `feature_mode` 是否有效

优势：
- 跑得快
- 预测链路最完整
- 方便对外部测试集统一推理

## 2.4 NN 子家族一：RNN/序列递归类

### 当前主流程直接使用的文件

- `template/models/lstm.py`
  - 注册名 `lstm`。LSTM 主实现（残差/注意力等更符合实际建模）。
  - 结构：输入投影、LSTM 主干、可选 attention、可选残差（start/middle/end）、可选 ID embedding、MLP head。

- `template/models/GRUModel.py`
  - 注册名 `gru`。GRU 主实现（含残差 head）。
  - 结构：输入投影、GRU 主干、残差全连接 head、可选 ID embedding。

- `template/models/Attention_GRUModel.py`
  - 注册名 `attention_gru`。带 attention 聚合的 GRU 版本。
  - 相比普通 GRU，多了一层时间维 attention 汇聚。

### 投研建议

如果你想先比较“传统序列建模”的收益，建议顺序：

1. `lstm`
2. `gru`
3. `attention_gru`

原因：
- 这三类的归纳偏置最接近，适合先做同一组 lookback 下的横向比较。
- 它们对数据规模和训练稳定性的要求通常低于 Transformer/Autoformer。

## 2.5 NN 子家族二：卷积时序类

- `template/models/TCNModel.py`
  - 注册名 `tcn`。
  - TCN 主实现。
  - 结构是：
    - 多层 dilated temporal conv
    - 残差连接
    - 可选 ID embedding
    - 输出裁剪选项

投研定位：
- 如果你怀疑目标更多依赖局部时间模式而不是长依赖，`tcn` 很适合做比较。

## 2.6 NN 子家族三：Transformer 系列

### 当前主流程直接使用的文件

- `template/models/TransformerModel.py`
  - 注册名 `transformer`。
  - 编码器-解码器版本的 Transformer。
  - 依赖：
    - `layers/Embed.py`
    - `layers/SelfAttention_Family.py`
    - `layers/Transformer_EncDec.py`
- `template/models/Transformer_Enc.py`
  - 注册名 `transformer_encoder`。仅编码器版本的 Transformer。
  - 更像一个 encoder-only backbone，再接一个回归 head。

### 相关底层组件

- `template/models/layers/Embed.py`
  - 各类 embedding 层，包括位置编码、token embedding、时间 embedding 等。
- `template/models/layers/SelfAttention_Family.py`
  - 多种 attention 实现与包装层。
- `template/models/layers/Transformer_EncDec.py`
  - Transformer 编码器、解码器及规范化构件。

### 投研定位

适合做：
- 验证长依赖和跨时间步交互是否能带来增益
- 比较 encoder-only 与 encoder-decoder 两种架构口径

建议先从：
1. `transformer_encoder`
2. `transformer`

开始试，因为 encoder-only 往往更稳、更容易调。

## 2.7 NN 子家族四：Autoformer 系列

### 当前主流程直接使用的文件

- `template/models/AutoformerModel.py`
  - 注册名 `autoformer`。标准 Autoformer 风格实现。
  - 依赖：
    - `layers/AutoCorrelation.py`
    - `layers/Autoformer_EncDec.py`
    - `layers/Embed.py`
- `template/models/Autoformer_encoderModel.py`
  - 注册名 `autoformer_encoder`。Autoformer 的 encoder-only 变体。
  - 同样支持时序分解和 autocorrelation 风格模块。

### 相关底层组件

- `template/models/layers/AutoCorrelation.py`
  - AutoCorrelation 与其 layer 封装。
- `template/models/layers/Autoformer_EncDec.py`
  - Autoformer 的 encoder/decoder 组件。

### 投研定位

适合做：
- 验证趋势/季节性分解类结构是否更适合当前因子时序
- 比较 Autoformer 与普通 Transformer 的差异

建议先试：
1. `autoformer_encoder`
2. `autoformer`

## 2.8 `models/layers/`：底层时序组件库

这部分文件大多不是投研直接调用的入口，但它们是复杂时序网络的“积木层”。其中一部分当前主流程会直接间接用到，另一部分更像未来扩展储备。

- `template/models/layers/Embed.py`
  - 各类 embedding 与位置编码模块。
- `template/models/layers/SelfAttention_Family.py`
  - 多种注意力实现，包括 full/prob/reformer/two-stage attention。
- `template/models/layers/Transformer_EncDec.py`
  - Transformer 编解码器基础模块。
- `template/models/layers/AutoCorrelation.py`
  - Autoformer 的 autocorrelation 核心模块。
- `template/models/layers/Autoformer_EncDec.py`
  - Autoformer 编解码结构。

下面这些文件更多是底层组件库或扩展储备，当前注册表未直接暴露为独立模型：

- `template/models/layers/Conv_Blocks.py`
  - Inception 风格卷积块。
- `template/models/layers/Crossformer_EncDec.py`
  - Crossformer 风格编解码模块。
- `template/models/layers/DWT_Decomposition.py`
  - 小波分解相关算子。
- `template/models/layers/ETSformer_EncDec.py`
  - ETSformer 风格时序模块。
- `template/models/layers/FourierCorrelation.py`
  - Fourier block 与 Fourier cross attention。
- `template/models/layers/MultiWaveletCorrelation.py`
  - 多小波相关性模块。
- `template/models/layers/Pyraformer_EncDec.py`

阅读建议：
- 如果你只是做投研模型对比，先不用深入这些文件。

## 3. 投研过程中你实际该怎么做，才能系统比较不同模型效果

## 3.1 第一步：先固定比较口径

无论你比较什么模型，建议先固定以下维度：

- 标签列：如 `LabelA`
- 特征口径：如 `feature_mode=no_missing`
- 数据切分比例：默认时间切分即可
- 随机种子：如 `seed=42`
- 最大训练行数：如先固定一个较小可迭代的值

目的：
- 保证不同模型的比较是公平的
- 避免把“数据口径变化”误判成“模型提升”

## 3.2 第二步：先跑 GBDT baseline

推荐顺序：

1. 先跑 `lgbm`
2. 再跑 `xgb`

原因：
- 这两类最快，能给你一个最基本的基准线。
- 如果 GBDT 都没有稳定信号，直接上复杂 NN 往往性价比不高。

示例命令：

```bash
python template/runners/train.py --family lgbm --label-col LabelA --feature-mode no_missing --seed 42
python template/runners/train.py --family xgb --label-col LabelA --feature-mode no_missing --seed 42
```

重点看：
- `meta.json` 中的 `mse/mae/r2/ic/rankic`
- 不同 `feature_mode` 下是否稳定

## 3.3 第三步：在 NN 里先比简单模型，再比复杂模型

建议顺序：

1. `lstm`
2. `gru`
3. `attention_gru`
4. `tcn`
5. `transformer_encoder`
6. `transformer`
7. `autoformer_encoder`
8. `autoformer`

示例命令：

```bash
python template/runners/train.py --family nn --nn-model lstm --label-col LabelA --feature-mode no_missing --lookback 32 --seed 42
python template/runners/train.py --family nn --nn-model gru --label-col LabelA --feature-mode no_missing --lookback 32 --seed 42
python template/runners/train.py --family nn --nn-model transformer_encoder --label-col LabelA --feature-mode no_missing --lookback 32 --seed 42
```

为什么这样排：
- 简单模型更容易判断“序列建模是否有增益”。
- 复杂模型需要更久训练和更多调参，不适合一开始就全量铺开。

## 3.4 第四步：每次只改一类变量

推荐每轮实验只改变一类因素：

- 只换模型，不换数据口径
- 只换 lookback，不换模型
- 只换 loss，不换 lookback
- 只换 feature_mode，不换其他超参

这样做的好处：
- 你能知道提升来自哪里
- `experiment_log`、`meta.json` 才有可比较性

## 3.5 第五步：结果优先看什么

建议优先顺序：

1. `r2`
2. `rankic`
3. `ic`
4. `mae/mse`
5. 回测结果

原因：
- 当前这套训练管线已经把 `R^2` 纳入训练、checkpoint 与独立评估闭环，它也是更接近官方最终口径的指标。
- 对投研来说，排序能力仍然重要，所以 `rankic/ic` 依然值得和 `r2` 一起看。
- 如果只看单一误差项或只看单一排序指标，都可能高估模型价值。

## 3.6 第六步：什么时候该用哪些评估模块

### 训练阶段

优先看：
- `train.py` 输出的 `meta.json`

### 独立复评阶段

用：
- `template/runners/evaluate.py`

适合：
- 你已经把 `predict.py` 的两列预测结果与真实标签表按主键对齐，得到包含 `prediction + y + date` 的 parquet
- 想脱离训练过程独立检查指标

### 更深入研究阶段

用：
- `template/eval/backtest.py`
- `template/eval/factor_backtest.py`
- `template/eval/plots.py`
- `template/eval/experiment_log.py`

适合：
- 做分层收益、多空净值、实验对比
- 从“模型能拟合”升级到“模型能不能转化成策略表现”

## 3.7 第七步：外部测试集推理时要注意的差异

现在 `GBDT` 和 `NN` 都能通过统一的 `template/runners/predict.py` 对外部 `test.parquet` 做推理，但二者仍有使用层面的差异：

- `GBDT` 是逐批表格推理，天然对称。
- `NN` 需要依赖 `lookback` 滑窗，因此外部测试集开头的一小段样本会先作为窗口预热，再逐步产生预测。

因此在投研里，更建议你按下面两层口径看结果：

1. 先比较训练阶段保存的验证/holdout 指标，尤其是 `r2`、`rankic`、`ic`
2. 再比较统一外部测试集上的预测产物和独立复评结果

这样更容易区分“模型在内部切分上有效”与“模型在真实外推场景里可复用”这两类问题。

## 4. 一份实用的投研实验路线图

如果你现在的目标是“尽快知道什么模型更值得继续投入”，建议按下面路线推进：

### 阶段 A：先判断信号有没有

1. 跑 `lgbm`
2. 跑 `xgb`
3. 比较 `LabelA/B/C`
4. 比较 `all / no_missing / top_ic`
5. 比较不同标准化模式，如 `global / cross_section / date / time_rolling`

如果这一步指标都不稳定，优先回去看：
- 标签定义
- 特征质量
- 预处理

### 阶段 B：验证序列建模值不值得

1. 跑 `lstm`
2. 跑 `gru`
3. 跑 `attention_gru`
4. 固定 `lookback` 做横向比较
5. 如果显存或内存紧张，优先保持较小 `lookback` 与较稳的 batch 配置

如果 RNN 系列明显优于 GBDT，说明时序结构有价值。

### 阶段 C：验证更复杂结构能否继续增益

1. 跑 `tcn`
2. 跑 `transformer_encoder`
3. 跑 `transformer`
4. 跑 `autoformer_encoder`
5. 跑 `autoformer`

如果复杂模型没有明显增益，通常就不要急着继续堆结构。

### 阶段 D：从“拟合”走向“策略”

1. 用 `eval/metrics.py` 看 `R^2/IC/RankIC`
2. 用 `eval/backtest.py` 看分层和多空
3. 用 `eval/plots.py` 看曲线稳定性
4. 用 `eval/experiment_log.py` 做实验留档

## 5. 如果你后续要新增模型，应该改哪些文件

以新增一个新的 NN 模型为例，通常需要改：

1. 在 `template/models/` 下新增实际模型文件
2. 在 `template/models/registry.py` 中注册模型名
3. 在 `template/models/__init__.py` 中从该模块 import 并加入 `__all__`
4. （可选）如需专用参数，在 `template/configs/pipeline_config.py` 的 `NNConfig` 中增加对应字段
5. 用 `template/runners/smoke.py` 验证能否实例化和跑通

如果是新增 GBDT 变体，则通常要改：

1. `template/models/gbdt/`
2. `template/train/gbdt_trainer.py`
3. `template/configs/presets/`
4. `template/runners/train.py`

  - `template/runners/evaluate.py`

  - `template/data/parquet_adapter.py`
  - `template/data/preprocess.py`
  - `template/data/nn_samples.py`

  - `template/models/registry.py`
  - `template/models/gbdt/*.py`

  - `template/models/GRUModel.py`

如果只看一句话来理解这个模板：

它本质上是一个“统一 runner 驱动、统一 parquet 数据适配、支持低内存 NN 训练、统一 `R^2/IC/RankIC` 指标闭环、并支持 GBDT 与多类时序神经网络横向比较”的投研实验模板。
